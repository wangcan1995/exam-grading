# 试卷扫描 + 阅卷打分系统 — 整体技术方案

## 一、需求摘要
- **模式**：AI 辅助判分 + 人工复核（AI 先判，人在 Web 端复核/修改/批注）
- **题型**：客观题（选择/判断）、填空题、简答/解答题、作文（全覆盖）
- **技术栈**：Python 全栈

## 二、系统整体架构（五层）
```
① 前端层  Vue3 + Vite + Element Plus + Fabric.js
② 网关/API层  FastAPI + WebSocket + JWT
③ 业务服务层  扫描归档│切题分发│任务编排│判分调度│复核流转
④ AI 能力层  图像处理(OpenCV) │ OCR(PaddleOCR) │ LLM判分
⑤ 存储层  PostgreSQL + Redis + MinIO + Celery
```

## 三、核心数据流
```
纸张试卷 → 扫描/拍照
  → ① 预处理(矫正/去噪/二值化)
  → ② 锚点定位 → 透视矫正
  → ③ 题块切分
     ├ 客观题 → OMR涂卡检测 → 自动判分
     ├ 填空题 → 手写OCR → 文本比对
     └ 简答/作文 → LLM判分(分数+理由)
        → ⑦ 待复核队列
        → ⑧ 人工复核(接受/修改/批注)
        → ⑨ 出分 + 错题分析
```

## 四、各题型判分策略

### 客观题 — 全自动 >99%
涂卡检测 + 标准答案比对，多涂/未涂进人工队列。

### 填空题 — OCR + 比对
PaddleOCR 识别 → 精确匹配 + 等价判断(1/2=0.5=二分之一) → 低置信度进人工。

### 简答题 — LLM + 复核
题干+采分点+答案 → LLM 输出分数+命中情况+理由(JSON) → 必须人工复核。

### 作文 — LLM 多维评分
内容/结构/语言/卷面 各维度独立打分 + 评语 → 必须人工复核。

**置信度分流**：每结果带 confidence，低于阈值自动进人工队列。

## 六、技术难点与应对

| 难点 | 应对 |
|---|---|
| 拍照歪斜定位不准 | 四角锚点+透视变换，无锚点用边缘兜底 |
| 手写OCR准确率瓶颈 | 置信度分流+人工兜底 |
| LLM判分不一致 | 结构化prompt+temperature=0+缓存+人工复核 |
| 试卷排版多样 | 答题卡模板编辑器(可视化框选) |
| 图片存储性能 | MinIO+缩略图+懒加载 |
